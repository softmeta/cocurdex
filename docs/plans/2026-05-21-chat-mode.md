## Context

目前 cocurdex 桌面端的 `chat` 功能（`apps/desktop/src/features/chat`）是绑定在 coding agent session 上的：每条会话必须挂在 workspace 下、由 `AgentRuntimeManager` 调度某个 CLI 适配器（claude-code / codex / gemini-cli / opencode / pi），UI 充满了工具调用、权限请求、计划面板等交互。

用户希望再加一种类似 ChatGPT / Gemini 网页版的纯对话模式：与 workspace 无关、不跑 agent loop、不调工具，只是「人 ↔ LLM」流式聊天。

**用户确认的设计选择**：
- 顶层独立模式（与 workspaces / sessions 并列的入口）
- LLM 接入走 [Vercel AI SDK (`ai`)](https://github.com/vercel/ai)，结合用户已配置的 provider
- 首版功能：流式文本 + 图片多模态 + 自动生成标题 + 系统提示词预设 + web search

**不复用 agent 体系的理由**（已与用户确认）：
- `sessions.workspace_id NOT NULL` 与 `AgentRuntimeManager` 全路径都吃 `workspaceRootPath`，复用需要动地基；
- 现有 agent 全是 CLI 适配器，要做"填 API key 就能用"的 ChatGPT 体验仍需新写一个 HTTP/SDK adapter，工作量不省；
- agent 协议里的 permission / question / subagent / provider_session 等概念在纯 chat 下是噪音，会在 `chat-view.tsx`（921 行）里制造大量 `if (isChatMode)` 分支。

## 总体方案

把「Conversations」作为一种与 `sessions` 解耦的新顶层实体，新建独立的表、daemon service、RPC 通道、前端 feature。复用现有的 `provider_configs` / `provider_models` / `provider_secrets` 体系来定位模型与密钥；LLM 调用统一通过 Vercel AI SDK 的 provider 抽象完成。

不复用 `sessions` 表的原因：sessions 强耦合 workspace、agent runtime、tool_calls、permissions、provider_session 等概念；硬塞 `agent_type='chat'` 会污染所有 agent 分支逻辑且需要大量 `if` 判空。新表更干净，也便于以后单独迭代（分享对话、folder 分组、记忆等）。

## 一、后端 (`packages/`)

### 1. 数据模型 — 新表 (`packages/db/src/schema.ts`)

新增两张表（不动现有 sessions / messages）：

```sql
CREATE TABLE IF NOT EXISTS conversations (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  provider_id TEXT NOT NULL,
  model_id TEXT NOT NULL,
  system_prompt TEXT,
  preset_id TEXT,                 -- 关联角色预设（可空）
  web_search_enabled INTEGER NOT NULL DEFAULT 0,  -- 该会话是否启用 web search
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  last_message_at TEXT,
  archived_at TEXT,
  FOREIGN KEY (provider_id, model_id)
    REFERENCES provider_models(provider_id, model_id) ON DELETE SET NULL
);

CREATE TABLE IF NOT EXISTS conversation_messages (
  id TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  role TEXT NOT NULL,             -- 'user' | 'assistant' | 'system'
  content_json TEXT NOT NULL,     -- Vercel AI SDK 的 ModelMessage parts（text/image/tool-call/tool-result/source）
  status TEXT NOT NULL,           -- 'pending' | 'streaming' | 'completed' | 'errored'
  usage_json TEXT,                -- prompt/completion tokens
  sources_json TEXT,              -- web search 引用列表（url/title/snippet），便于直接渲染不再 join
  error TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_conv_messages_conv_created
  ON conversation_messages(conversation_id, created_at);
```

可选：`conversation_presets`（角色预设）— 首版若仅需「自定义 system prompt」可省，预设硬编码在前端常量即可。建议先省。

### 6. Web search

利用 Vercel AI SDK 内置的 tool-use 循环，**不需要自建 agent loop**。首版走 provider-hosted 方案，零自建后端、按 provider 计费，模型自己决策何时搜、自动返回 source。

`packages/llm-chat` 里集中映射：

```ts
// packages/llm-chat/src/web-search.ts
import { openai } from '@ai-sdk/openai'
import { anthropic } from '@ai-sdk/anthropic'
import { google } from '@ai-sdk/google'

export function buildWebSearchTools(providerKind: ProviderKind) {
  switch (providerKind) {
    case 'openai':
      return { web_search: openai.tools.webSearchPreview() }
    case 'anthropic':
      return {
        web_search: anthropic.tools.webSearch_20250305({ maxUses: 5 }),
      }
    case 'google':
      // Gemini 用 grounding 配置而非 tools 字段，在 model options 注入
      return { __googleGrounding: true }
    case 'openai-compatible':
      return null   // 不支持，UI 上禁用 web search 开关
  }
}
```

`streamChat` 内部：
- 普通 chat：`streamText({ model, messages, system })`
- 启用 web search：`streamText({ model, messages, system, tools, stopWhen: stepCountIs(5) })`（OpenAI / Anthropic 路径），Google 路径走 model option 的 `useSearchGrounding`
- 通过 `result.fullStream` 拿到 `tool-call` / `tool-result` / `source` 三类事件，统一映射成 `ChatStreamDelta`

**前端 UI**：composer 旁加一个 `Globe` 图标的 toggle，对应 `web_search_enabled`。会话中渲染：
- 模型正在搜索时：消息上方 chip「🔎 Searching the web…」（来自 `tool-call` 事件）
- 结果到达：chip 变成「Searched N sites」可展开
- 完成消息底部：`Sources` 区列出 url + 标题（来自累积的 `source` 事件，存进 `sources_json`）

无新组件需求外的依赖：仍是 `MessagesSquare` / `Globe` 等 `lucide-react` 图标 + 现有 shadcn 组件，遵循 `size-4` 一致性。

**provider 能力检测**：`packages/llm-chat` 导出 `supportsWebSearch(providerKind, modelId)`，前端 `model-picker.tsx` 用它给不支持的模型自动灰掉 web search 开关；`chat-service` 在 `sendMessage` 入口再 double-check，若不支持则忽略 flag 并在响应中带 warning。

**首版只做 provider-hosted**。其余路线见 §6.1 / §6.2 / §6.3，全部走 AI SDK 的 tool loop，**不引入新 agent loop**，且共享同一套 UI（搜索 chip / sources 区 / 步骤展开）与事件协议。

### 6.1 自建 search API（Brave / Tavily / SerpAPI）— v1.5

定位：用户自带 search key，跨 provider 通用（OpenAI-compatible / 本地模型也能用），按次计费可控。

新增表存用户配置（与 `provider_secrets` 同款 KMS 加密）：

```sql
CREATE TABLE IF NOT EXISTS search_providers (
  id TEXT PRIMARY KEY,            -- 'brave' | 'tavily' | 'serpapi' | 'exa'
  enabled INTEGER NOT NULL DEFAULT 1,
  api_key_secret_id TEXT,         -- 复用 provider_secrets 表
  config_json TEXT,               -- 各家差异化参数（safesearch、country、result_count）
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

`packages/llm-chat` 抽出策略：

```ts
// packages/llm-chat/src/search-providers.ts
export interface SearchProvider {
  id: 'brave' | 'tavily' | 'serpapi' | 'exa'
  search(query: string, opts?: SearchOpts): Promise<SearchResult[]>
}

// 各家 HTTP 客户端（注意速率限制 + 超时 + 重试）
export function createBraveSearch(apiKey: string): SearchProvider     // https://api.search.brave.com/res/v1/web/search
export function createTavilySearch(apiKey: string): SearchProvider    // https://api.tavily.com/search  ← 自带 LLM 友好的 content extraction
export function createSerpAPISearch(apiKey: string): SearchProvider   // https://serpapi.com/search
export function createExaSearch(apiKey: string): SearchProvider       // https://api.exa.ai/search  ← 语义搜索
```

注入成 AI SDK tool：

```ts
// packages/llm-chat/src/web-search.ts
import { tool } from 'ai'
import { z } from 'zod'

export function buildCustomSearchTools(provider: SearchProvider, fetchPage?: PageFetcher) {
  return {
    web_search: tool({
      description: 'Search the web. Returns title/url/snippet for each hit.',
      inputSchema: z.object({
        query: z.string(),
        count: z.number().min(1).max(10).default(5),
      }),
      execute: async ({ query, count }) => provider.search(query, { count }),
    }),
    // Tavily 自带 extract；其它家需要单独抓页面
    ...(fetchPage ? {
      fetch_url: tool({
        description: 'Fetch and extract readable content from a URL.',
        inputSchema: z.object({ url: z.string().url() }),
        execute: async ({ url }) => fetchPage(url),  // 走 Readability / Mozilla readability
      })
    } : {}),
  }
}
```

`streamChat` 的 `webSearch` 参数升级成策略对象：`{ kind: 'provider-hosted' } | { kind: 'custom', provider: SearchProvider }`。`stopWhen: stepCountIs(5)` 控制循环深度。

各家差异速查：

| 服务 | 关键特点 | 价格 | 适用 |
|---|---|---|---|
| **Tavily** | 专为 LLM 设计，自带 content extraction + answer 字段 | 1000 free/月，之后按次 | **推荐首选** — 单 API 解决搜+读 |
| Brave | 隐私友好，质量稳，纯 search 不带 extract | 2000 free/月 | 配合 fetch_url 工具 |
| SerpAPI | Google/Bing/百度多引擎聚合 | 100 free/月，$50+/月起 | 需要中文 / 特定区域 |
| Exa | 语义搜索 + neural ranking | 1000 free/月 | 研究类问题、找相似页面 |

UI：Settings 新增 "Search providers" 页（仿 `provider-configs` 表的现有 UI 模式），每家填 API key + 测试连通；Chat 顶部 web-search toggle 旁加一个 provider 下拉。

`fetch_url` 的页面抓取走 daemon 端 fetch（避免 CORS），用 [`@mozilla/readability`](https://github.com/mozilla/readability) + JSDOM 抽正文，输出 markdown，token 占用比 raw HTML 低一个量级。

### 6.2 内置 BrowserPanel 工具化 — v2

复用现有 `apps/desktop/src/features/browser`（已有 webview + url-bar + annotation）。把它的能力包成 tool，让 LLM 操作内置浏览器面板。

新增 `desktopApi.browser*` 命令（Tauri 侧）：
- `browser.navigate(url)`
- `browser.snapshot()` — a11y tree，节点带 `ref` 编号
- `browser.click(ref)` / `browser.type(ref, text)` / `browser.scroll(ref?, deltaY)`
- `browser.screenshot()` — 返回 base64 png，作为 image part 喂给视觉模型
- `browser.wait_for(ref | networkIdle, timeoutMs)`

`packages/llm-chat` 增加 `buildBrowserTools(desktopApi)` 返回上述 tool 集合。事件流复用现有 `tool-call` / `tool-result` 渲染，UI 上把"内置浏览器面板"和 chat 并排显示，用户能实时看到 agent 在干什么。

关键工作：
- 后台 tab 池：当前 BrowserPanel 单实例会和用户视图抢用。需要支持隐藏 webview 实例，或为 chat 分配独立 pane。
- a11y snapshot 抽取：在 webview 注入 content script，类似 Playwright 的 `_snapshotForAI`，输出节点树 + 稳定 ref。
- 中断：tool execute 响应 abort signal，停止当前导航。

### 6.3 外置浏览器扩展（用户日常浏览器）— v3

**目标**：使用用户**已登录的**日常浏览器（Chrome/Edge/Brave/Arc 等 Chromium 系优先），解锁"读我的私有 dashboard"、"在我已登录的 Linear 创建 issue"这类场景。

**架构**：

```
LLM (AI SDK tool loop)
   ↓
daemon (ws://127.0.0.1:<port>, 一次性配对码)
   ↕  WebSocket（带 protocol versioning + capability negotiation）
Chrome Extension (MV3, service worker + content script)
   ↓ chrome.tabs / chrome.scripting
用户真实浏览器（共享 cookie / MFA / 历史指纹）
```

新增 workspaces：
- `apps/extension-chrome/`（独立 Vite + CRX 构建，产物上 Chrome Web Store）
- `packages/browser-bridge/`（daemon 端 WS server + 协议 schema，前后端共享 zod 类型）

**配对流程**：
1. daemon 启动时在 localhost 起 WS server，生成 6 位 token
2. Chat UI 新增 "Connect browser" 入口，显示 token + 浏览器扩展安装链接
3. 扩展弹窗输入 token + daemon 端口 → 完成绑定，token 持久化到扩展 storage
4. 之后 WS 每次握手用该 token 鉴权

**Tool 集合**：与 §6.2 同构（`browser_navigate / snapshot / click / type / screenshot / wait_for`），实现层不同——execute 只是往 WS 丢一条消息等回包。因此 §6.2 沉淀的协议在 v3 直接复用，只换 transport。

**关键挑战**：

| 挑战 | 缓解 |
|---|---|
| Chrome Web Store 审核 1-2 周，更新慢 | 早做、版本号语义化、protocol 兼容 |
| `<all_urls>` 权限吓人 | 文案 + 默认 deny-list 高敏域名（银行/邮箱），用户主动 opt-in |
| Agent 和用户在同一浏览器抢操作 | 每个 chat 会话独占一个标记 tab（title 前缀 + 顶部 banner），不在用户当前 tab 执行 |
| 安全：扩展被恶意 daemon 控制 = RAT | 配对码 + origin 校验 + 写操作（click/type/submit）默认弹确认或显式 trust 域名 |
| 跨浏览器分裂 | 首版只做 Chromium 系（一份 MV3 包覆盖 Chrome/Edge/Brave/Arc）；Safari/Firefox 后置 |
| Captcha / 反爬 | 用户登录态 + 真实指纹基本免疫；遇 captcha 时 tool 返回特殊状态 → chat UI 提示用户在浏览器中手动完成后点"继续" |
| 协议演进 | WS 消息带 `protocolVersion`，握手时双向 capability negotiation；老扩展 + 新 daemon 时降级 |

**与 §6.2 的边界**：内置 BrowserPanel 适合需要"可视化跟踪 + 不要污染日常浏览器"的场景；外置扩展适合需要登录态。两者可同时存在，UI 上让用户选目标。

### 6.4 三层方案路由

最终在 `streamChat` 里按用户在 chat UI 的选择路由：

| 用户选择 | 走哪条 | 适用场景 |
|---|---|---|
| Web search: off | 无 tools | 纯聊天 |
| Web search: Provider-hosted (§6) | provider 内置 tool | 公开信息、最省成本 |
| Web search: Custom API (§6.1) | Brave / Tavily / ... | 跨 provider 通用，自带 key |
| Browse: Built-in (§6.2) | BrowserPanel tools | 需要复杂浏览且不要登录态 |
| Browse: My browser (§6.3) | Extension WS bridge | 需要登录态 / 私有 dashboard |

UI 上 Web search 与 Browse 是两个独立 toggle（不互斥；都启用时把两组 tools 合并丢给模型，让它自己选）。`buildToolset(conversation, capabilities)` 是统一入口，返回最终 tools 对象给 `streamText`。

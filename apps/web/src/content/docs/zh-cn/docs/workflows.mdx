title: 工作流
description: 由 daemon 掌管的多步骤工作流(计划、实现、评审),从 CLI 或桌面端驱动。
---

**工作流**是由 daemon 掌管的多步骤运行,协调多个 Agent 角色——通常是 计划 → 实现 → 评审——并带有需要你批准或拒绝的显式关卡。

它们独立于任何单个 provider 内部的「计划模式」。一个工作流有自己的运行 id、步骤列表和状态机。

## 什么时候用工作流

| 用工作流的场景 | 更适合单会话的场景 |
| --- | --- |
| 你想要结构化的 planner / implementer / reviewer 角色 | 任务只需要一个短循环 |
| 你想在实现继续之前有一道显式的批准关卡 | 你会亲自引导一个 Agent |
| 你想用 CLI/`tui` 监督长时间的多 Agent 运行 | 你只需要一个面板里的对话 + 工具 |

## 默认角色

| 角色 | 默认 Agent | 权限画像 |
| --- | --- | --- |
| Planner | `codex` | 只读画像 |
| Implementer | `grok-build` | 工作区写入 |
| Reviewer | `codex` | 只读画像 |

用 flags 覆盖:

```bash
cocurdex workflow create \
  --workspace /path/to/project \
  --prompt "Add signed download links for macOS" \
  --planner codex \
  --implementer grok-build \
  --reviewer codex
```

可选的模型覆盖:`--planner-model`、`--implementer-model`、`--reviewer-model`。要绑定保存好的 [Agent 角色](/docs/agents/#agent-角色)而非临时 Agent/模型组合,使用 `--planner-role`、`--implementer-role` 或 `--reviewer-role`。`--definition <id>` 可选择非默认的工作流定义。

## 命令

```bash
# 列出可用定义
cocurdex workflow definitions

# 创建运行(不总是自动开始——用 start 或 tui)
cocurdex workflow create --workspace <id|path> --prompt "<goal>"

# 列出运行
cocurdex workflow list

# 查看
cocurdex workflow show <run-id>

# 启动 / 关卡 / 取消
cocurdex workflow start <run-id>
cocurdex workflow approve <run-id> [--reason "..."] [--step <step-id>]
cocurdex workflow reject <run-id> [--reason "..."] [--step <step-id>]
cocurdex workflow cancel <run-id>
```

### 交互式 TUI

```bash
# 最近一次运行,或带 flags 创建并启动
cocurdex workflow tui
cocurdex workflow tui <run-id>
cocurdex workflow tui --workspace . --prompt "..."
```

工作流 TUI 不支持 `--json`。用它观察步骤、裁决关卡和取消。

## 生命周期(操作者视角)

1. 用工作区 + 目标和角色绑定**创建**一次运行。
2. **启动**运行(或用带创建 flags 的 `workflow tui`)。
3. 观察步骤流转——内置定义运行 **plan → approve_plan(关卡)→ implement → validate → review**,review 可以要求修改并回到 implement 循环。
4. 当**关卡**需要你时,**批准**或**拒绝**,可附理由(`--step` 默认指向 `approve_plan` 关卡)。
5. 目标变了或运行卡住时**取消**。拒绝计划关卡会把运行终结为 cancelled;校验失败或评审受阻会把运行终结为 blocked。

具体的步骤 id 取决于工作流定义版本。除非固定了某个已知定义,否则脚本里优先用 `workflow show` / TUI,而不是硬编码步骤名。

## 与会话的关系

- 工作流在 daemon 之下**编排**多次 Agent 执行。
- 常规**会话**仍是桌面工作台中单个 Agent 对话的单元。
- 你可以一边让工作流跑更正式的流水线,一边继续用并行会话做临时工作。

## 与产品 Skills 的关系

`/cocurdex-ship` 这类 Skills 帮助 Agent 针对某个 **Issue** 实现。工作流是 **daemon 级**的多 Agent 流水线。两者可结合:skills 管产品知识纪律,工作流管多角色执行。

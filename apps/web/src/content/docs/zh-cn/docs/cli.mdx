**`cocurdex` CLI** 是应用私有产品数据和 daemon 操作受支持的命令行边界。外部工具和 Agent 应该使用 CLI,而不是读取私有数据库文件。

大多数数据和会话命令需要**桌面 daemon**(通常在打开桌面应用时启动)。

## 安装

当 CLI 随桌面应用打包时,从 **Settings → CLI** 安装启动器,让 `cocurdex` 出现在 `PATH` 上。

```bash
cocurdex --version
cocurdex --help
```

在 monorepo 开发中,使用 workspace 里的 CLI 包(`apps/cli`)。

### 找到桌面二进制

打开流程需要 Cocurdex / Electron 二进制。解析顺序包括:

1. `COCURDEX_ELECTRON` 环境变量
2. 正运行在 Electron / 打包应用内
3. monorepo 下开发用的 `node_modules/electron`
4. 常见 macOS 安装路径(`/Applications/Cocurdex.app/...`)

解析失败时,先打开一次桌面应用并安装 CLI 启动器,或设置 `COCURDEX_ELECTRON`。

## 全局 flags

| Flag | 含义 |
| --- | --- |
| `--help` / `help` | 打印用法 |
| `--version` / `-v` / `-V` / `version` | 打印 CLI 版本 |
| `--json` | 支持处输出机器可读结果 |

## 打开桌面应用

VS Code 风格的文件夹打开:

```bash
cocurdex                 # 打开应用
cocurdex .               # 把当前目录作为工作区打开
cocurdex open            # 打开应用
cocurdex open /path/to/project
```

## 笔记

```bash
cocurdex note list [--json]
cocurdex note show <id> [--json]
cocurdex note create --title <title> [--body <markdown>] [--parent <id>] [--workspace <id>] [--folder] [--json]
cocurdex note update <id> [--title <title>] [--body <markdown>] [--json]
cocurdex note delete <id> [--json]
cocurdex note backlinks <id> [--json]
cocurdex note tags [note-id] [--json]
```

| Flag | 含义 |
| --- | --- |
| `--title` | 创建时必填 |
| `--body` | Markdown 正文(非文件夹时,在创建后应用) |
| `--folder` | 创建文件夹节点而非笔记 |
| `--parent` | 父级笔记/文件夹 id |
| `--workspace` | 可选的工作区关联 |

更新在底层使用乐观并发(revision)——始终优先用 CLI/桌面端,而非编辑 SQLite。

## Issue

默认视图 id 是 `project`,除非传入 `--view`。

```bash
cocurdex issue list [--status <column>] [--view <id>] [--json]
cocurdex issue show <id> [--view <id>] [--json]
cocurdex issue create --title <title> [--status <column>] [--priority <id>] [--body <text>] [--workspace <id>] [--view <id>] [--json]
cocurdex issue move <id> <column> [--view <id>] [--json]
cocurdex issue delete <id> [--view <id>] [--json]
cocurdex issue views [--json]
```

默认**状态**列:`backlog`、`doing`、`review`、`done`。
默认**优先级**列:`urgent`、`high`、`medium`、`low`、`none`。

示例:

```bash
cocurdex issue create --title "Fix download page" --status backlog --priority high
cocurdex issue move <id> doing
cocurdex issue list --status doing
```

## 搜索

```bash
cocurdex search <query> [--kind note|issue] [--workspace <id>] [--json]
```

## Skills

产品 skills 以 `cocurdex-*` 命名空间隔离。安装是**手动**的(非自动)。

```bash
cocurdex skills list [--json]
cocurdex skills status --scope project|global [--root <path>] [--json]
cocurdex skills install --scope project|global [--root <path>] [--json]
cocurdex skills remove --scope project|global [--root <path>] [--json]
```

`--root` 在 project 范围下默认为当前工作目录。`cocurdex skill` 也可作为别名。见 [Skills](/docs/skills/)。

## Daemon 与工作区

```bash
cocurdex daemon status
cocurdex workspace list
```

## 工作树

托管的 git 工作树为会话提供工作区仓库的隔离检出。

```bash
cocurdex worktree list [--json]
cocurdex worktree settings [--root <path>] [--fetch|--no-fetch] [--json]
cocurdex worktree create --workspace <id|path> --branch <name> [--start-point <rev>] [--json]
cocurdex worktree remove --workspace <id|path> --path <worktree-path> [--json]
```

不带 flags 的 `worktree settings` 打印当前设置;传 `--root` 和/或 `--fetch`/`--no-fetch` 则更新。`--root` 设置 Cocurdex 创建托管工作树的目录(置空则恢复默认位置);`--fetch` 控制创建工作树之前是否先 fetch 仓库。

## 会话

```bash
cocurdex session list
cocurdex session create --workspace <id|path> --agent <agent> --provider <provider> --model <model>
cocurdex session tui [session-id]
cocurdex session tui --workspace <id|path> --agent <agent> --provider <provider> --model <model>
cocurdex session send <session-id> <prompt>
cocurdex session stop <session-id>
```

| Flag | 必填场景 | 含义 |
| --- | --- | --- |
| `--workspace` | create / tui 创建 | 工作区 id 或文件系统路径 |
| `--agent` | create / tui 创建 | Agent id(`claude-agent`、`codex`、`opencode`、`grok-build`、`pi`) |
| `--provider` | create / tui 创建 | `provider list` 中的 provider 配置 id |
| `--model` | create / tui 创建 | `provider models` 中的模型 id |

不带 flags 的 `session tui` 附着到最近的非归档会话。它不支持 `--json`。

Agent id 与权限见 [Agent](/docs/agents/)。

## Provider

```bash
cocurdex provider list

```

## Agent 角色

保存好的 Agent 预设(Agent + provider/模型 + 权限 + 推理轴),也可以绑定工作流角色。在桌面 UI 中管理;从 CLI 列出:

```bash
cocurdex role list [--json]
```

## 工作流

daemon 掌管的多步骤运行(计划 → 实现 → 评审 风格)。完整说明见[工作流](/docs/workflows/)。

```bash
cocurdex workflow list
cocurdex workflow definitions
cocurdex workflow create --workspace <id|path> --prompt <prompt> \
  [--definition <id>] \
  [--planner <agent>] [--implementer <agent>] [--reviewer <agent>] \
  [--planner-model <model>] [--implementer-model <model>] [--reviewer-model <model>] \
  [--planner-role <id>] [--implementer-role <id>] [--reviewer-role <id>]
cocurdex workflow tui [run-id]
cocurdex workflow tui --workspace <id|path> --prompt <prompt> [...]
cocurdex workflow show|get <run-id>
cocurdex workflow start <run-id>
cocurdex workflow approve|reject <run-id> [--reason <text>] [--step <step-id>]
cocurdex workflow cancel <run-id>
```

不带 flags 时的默认角色 Agent:planner `codex`,implementer `grok-build`,reviewer `codex`。`--<role>-role` flag 绑定一个保存好的 [Agent 角色](#agent-角色)而非临时 Agent/模型组合;该角色的权限画像必须与工作流角色的要求匹配。

## CLI 不是什么

- 第二份事实源——本地数据库仍由桌面 daemon 掌管
- 多面板桌面工作台的完整替代品
- 云端团队管理工具(那会是独立的 console + API)
- 打开 `cocurdex.sqlite` 或私有 schema 路径的许可证

## 安全

不要把脚本指向 `cocurdex.sqlite` 或私有 schema 路径。它们是实现细节,预发布期间可能在没有兼容性承诺的情况下变化。优先使用 `--json` 输出和 CLI 返回的稳定 id。

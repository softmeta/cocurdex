## 工作区

**工作区**是 Cocurdex 挂接的项目上下文——通常是磁盘上的一个目录,Agent、终端和编辑器在其中工作。

| 属性 | 含义 |
| --- | --- |
| `id` | 稳定的工作区 id |
| `name` | 显示名(通常是文件夹名) |
| `rootPaths` | 磁盘上的绝对路径;首项是主根目录 |

从桌面 UI 打开,或:

```bash
cocurdex .
cocurdex open /path/to/project
cocurdex workspace list
```

会话和许多产品视图围绕当前工作区组织。笔记和 Issue 可选地关联到某个工作区 id 以便过滤;默认它们不是「项目树里的文件」。

## 应用私有数据

笔记、Issue、视图、标签、链接和搜索索引存放在**应用私有存储**(`cocurdex.sqlite`)中,而不是双写的 Markdown 树。

重要规则:

1. **桌面 daemon** 是唯一打开本地数据库的进程。
2. **CLI** 是自动化和 Agent 受支持的外部读写边界。
3. Markdown 导入导出是**显式**的——不是第二个活数据库。
4. 私有表结构和文件路径**不是**公开 API。
5. 预发布期间,缺少当前应用标记 / schema 版本的数据库可能被**重建**而非迁移。

### 什么存在哪里

| 数据 | 权威方 |
| --- | --- |
| 笔记、Issue、视图、标签、链接、FTS 索引 | Daemon + `cocurdex.sqlite` |
| Agent 角色、工作树设置、会话记录 | Daemon + `cocurdex.sqlite` |
| 托管的 git 工作树 | 由 daemon 在配置的工作树根目录下创建 |
| 项目源文件 | 磁盘上你的工作区目录 |
| Agent provider 授权(如 Codex) | 该工具自己的配置(例如 `~/.codex` 下) |
| 产品 skill 文件(可选) | 安装后的项目或全局 skills 目录 |
| monorepo 中的工程文档(`docs/adr` 等) | 你的仓库——不会自动发布到营销站 |

## 为什么这样设计

以路径为身份的文件树让稳定 id、事务、全文搜索和反向链接更难实现。SQLite 提供了这些性质,而不要求每个工具都去解析仓库。Agent 通过 `cocurdex note|issue|search …` 保持互操作,而不是另造平行的 `.scratch` 树。

## Daemon

Daemon 负责:

- 掌管数据库连接
- 通过文档化的 RPC 契约为桌面端和 CLI 服务
- 运行会话与工作流编排

```bash
cocurdex daemon status
```

如果 CLI 数据命令失败,打开桌面应用(或确认 daemon 进程可达),然后重试。

## 云端与团队(以后)

未来的团队控制台和云端 API 会为选定实体(很可能先是 Issue 和已发布文档)暴露**组织级投射**。这**不会**取代本机工作的本地写权威:

| 形态 | 角色 |
| --- | --- |
| 桌面端 + daemon | 本地写权威 |
| CLI | 本地自动化边界 |
| 未来的 `app.` 控制台 | 团队可见性 / 轻量协作 |
| 未来的 `api.` | 身份、组织、同步契约 |

面向贡献者的本地与云端边界记录在 monorepo ADR 中;同步的最终用户行为会随功能上线出现在这里。

## 安全检查清单

- 不要在脚本里打开或迁移 `cocurdex.sqlite`
- 不要把私有 schema 当集成面来爬取
- 优先使用 CLI `--json` 和返回的 UUID
- 在你显式发布之前,把产品笔记/Issue 当作私有
